# Contexto del proyecto

- **Propósito:** sistema web para reservar canchas de fútbol 5 y administrar reservas, pagos, ingresos y ocupación.
- **Stack:** Next.js 16 App Router, React 19, TypeScript estricto, Tailwind CSS 4, Radix UI, Lucide, Recharts; API Routes de Next.js; MySQL 8 mediante `mysql2/promise`.
- **Estructura:** `app/page.tsx` es la entrada pública; `app/layout.tsx` monta navegación y contexto de sesión. `app/booking`, `app/reservations` y `app/admin` contienen las pantallas. `app/api` contiene los endpoints REST; `app/components` la UI; `app/lib` la conexión y utilidades; `app/types/bookings.d.ts` los tipos compartidos. `proxy.ts` protege rutas de páginas.
- **Flujo principal:** el cliente consulta canchas, crea reservas y consulta/cancela las suyas. El admin revisa pagos en `/admin/payments`, cambia estados mediante `/api/admin/bookings/status`, consulta la agenda en `/admin/bookings` y las métricas en `/admin/stats`. Esta última página solicita `/api/admin/stats?from=YYYY-MM-DD&to=YYYY-MM-DD`, que agrega ingresos, estados, uso por cancha, deportes, horarios y registros de auditoría. `AuditSection` permite filtrar el registro y exportarlo a CSV.
- **Datos:** `init.sql` define `users` (roles `customer`/`admin`), `courts` y `bookings` con fechas, estado de reserva, estado/método de pago, precio, comprobante y datos del cliente. Una columna generada con índice único evita turnos activos duplicados. Las relaciones son `bookings.user_id → users` y `bookings.court_id → courts`.
- **Acceso:** login con `bcryptjs` y JWT `jose` en cookie HttpOnly. `proxy.ts` restringe `/admin/*` al rol admin; los endpoints sensibles usan además `getUserIsAdmin`. La UI usa `AuthContext` y `/api/auth/status`.
- **Configuración:** `.env.example` documenta `DATABASE_HOST/USER/PASSWORD/NAME/PORT` y `JWT_SECRET_KEY`; `app/lib/db.ts` admite también `DATABASE_URL` y `DATABASE_SSL`. `docker-compose.yml` levanta Next.js y MySQL con `init.sql`.
- **Convenciones:** componentes interactivos con `"use client"`; consultas SQL parametrizadas en rutas API; importaciones relativas en `app`; tipos de dominio globales en `app/types/bookings.d.ts`. Importes en USD y fechas de reservas `YYYY-MM-DD`.
- **Informes:** `/admin/stats` descarga un PDF desde `/api/admin/stats/pdf` para el rango elegido. El endpoint comprueba el rol admin y consulta todos los turnos del rango. `app/lib/pdf-report.ts` genera el PDF con tablas vectoriales, bordes y encabezados repetidos sin dependencias externas. Ingresos cobrados equivalen a `payment_status = 'paid'`; pendientes y reembolsos se muestran por separado. La tabla visible de auditoría y su CSV conservan el límite de 500 registros del API de estadísticas.
- **Comandos:** `npm install`, `npm run dev`, `npm run build`, `npm run start` (puerto 4002), `npm run lint`, `npm run seed:admin`. Para Docker: `docker compose up --build`.
